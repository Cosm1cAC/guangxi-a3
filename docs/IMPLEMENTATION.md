# 广西 A3 实现约定

来源：工作区《广西A3（尖3）棋牌规则.md》（2026-11-14 第10章修订）。

默认采用基础分制、每局 ♦4 首出、下家接风、同花最大牌优先、报单可压必打、过牌后允许再出。仅娱乐积分，多局累计。好友房下一局接口幂等。规则细则见规则文档第 10 章和第 17 章。

进贡／还贡采用共享规则引擎：2v2 全胜／全败为大贡，两名输方各交 2 张、两名赢方各收 2 张；半胜／半败为小贡，各交、各收 1 张；1、4 名同队为平局，不贡。独食全胜／全败与其余每家交换 2 张，半胜／半败交换 1 张。进贡者自动交出除 ♠A、♠3 外最大的牌到同一牌池。多名受贡者自由预选足额贡牌，全部无冲突后统一分牌；有冲突时可改选协商，或由冲突双方发起猜拳，手势双方提交后才公开、平手重来。胜者锁定预选，败者从剩余牌重选。受贡者逐张向所收贡牌的原交牌者等量返还，可退原贡牌，禁止返还 ♠A、♠3、♦4。单名受贡者直接收取全部贡牌。不设免贡／抗贡。全部还完每人 13 张，♦4 持有者首出。结算正确显示独食身份，自动补齐名次仅用于内部计算，界面不显示“补位”。

规则文档 6.5 / 7.2 的同花例子把 K 当作含 3、2 同花的最大牌，与 5.1 的总牌序冲突；实现依据明确的 5.1 总牌序（3 > 2 > A > K），顺子才使用自然序列。2v2 提前结算时未出完的同队成员按座位补名次，仅内部记录自动补齐的名次，不影响分数。

架构：共享纯 TypeScript 引擎；Web Vite + Three.js；原生小程序 WXML/WXSS + scoped Three.js；Node Express API；PostgreSQL JSONB 状态、行锁、版本号、对局记录。练习模式可离线运行，联机采用同一服务端裁判。Web 与小程序共享规则和场景构建函数，不共享 DOM。

视觉：山水茶室，石青 #173f48、湖绿 #397469、铜金 #d3b37b、米白 #eef0df、朱红 #b34c49。标题宋体，正文系统无衬线，数据等宽。核心视觉为铜鼓纹八方茶桌、远山与水面。牌面和装饰使用自制矢量/程序化几何，不依赖外部图片。

验收：八种牌型、状态推进与零和结算测试；机器人完整对局；API 隐私、非法动作与并发校验；Web 真浏览器流程与截图；小程序构建。微信真机需微信开发者工具及用户 AppID；发布还需 HTTPS API 域名。

出拳采用本机暂存选择 + 明确确认，只有确认按钮提交动作；新回合和平手后选择清空。真人座位不进入机器人自动动作。`view` 只在本人 `finishedNaturally` 且手牌为空时提供 `teammateHands`，仅列同阵营仍有牌的队友；未出完、补名次和独食无队友时为空。该数组逐次由服务端计算，客户端仅展示只读牌面。花色使用统一像素图，黑桃尖顶连贯轮廓、梅花分离三瓣，Web 3D、平面牌与原生界面共用。

好友房等待时首位成员是房主，服务端通过 `canFillBots` 返回可用操作。`POST /api/rooms/:id/fill-bots` 在房间行锁中校验登录、成员、房主和等待状态，只向空座追加 `userId:null, bot:true` 的机器人，保存成员并开局，自动推进到真人动作。加入、离席、补机器人共享行锁，不能覆盖真人或超出四座。机器人沿用共享规则处理局间进贡和回牌，不创建账号，也不计账号战绩。`scripts/room-bots-smoke.ts --browser` 在临时 schema 中验证真实接口、并发、跨设备座位、两局连打、强制大贡和网页横竖屏，结束后删除测试数据。

`POST /api/rooms/:id/join` 对已入座账号先返回原位；对新账号在进行中或结算的房间寻找 `bot:true,userId:null` 座位，优先仍有手牌者。接替只更新该成员、内部 `replacedBotRound` 和 `state.version`，手牌、轮次、身份、累计分和局间动作均保留；同一行锁串行处理抢位与出牌。成员元数据兼容已有房间，无需数据库迁移。`rankedRound` 要求四位真人且无人本局接替机器人，下一局自动恢复计分资格。三端轮询同时检查成员内容，座位数不变也会刷新名字、头像和机器人标识。隔离测试覆盖实时接替、最后一席并发、重连、进贡／猜拳／回牌、补名次和跨局计分，并在真实浏览器中验证加入与同桌同步。

邀请链接为固定入口 `/go/?room=<10位房号>`，入口保留查询参数转到当前牌桌。`src/core/room-invite.ts` 统一校验房号并生成无凭据链接。网页／安卓提供复制和可用时的系统分享，微信／抖音客户端复制相同链接。网页邀请优先于本机恢复牌局，`sessionStorage` 暂存待加入房号；登录令牌变化后续接邀请，成功或取消时清理参数和暂存，失败显示重试。接入原有鉴权加入接口，不新增匿名入座通路。真实浏览器验证复制／系统分享、已登录直入、刷新、错误密码、过期会话、满房、非法链接及接替机器人后的同桌同步。

手机布局集中在 `src/web/mobile.css`。`viewport.ts` 监听可见视口及安全区，布局尺寸变化才重设 3D 画布，键盘缩小时滚动到当前输入。名牌与提示按顶部导航、身份提示、底部操作的实测位置避让；低高度或大量手牌时收成单行名牌。平面手牌高度由 ResizeObserver 实测，3D 手牌抬高避开底部安全区，旋转后点击坐标仍使用实际画布边界。弹窗可滚动且限制在可见视口；贡牌确认区吸底并给聊天导航留位。`tests/browser/mobile-layout.spec.ts` 覆盖七种横竖屏尺寸、长昵称、13／15／19 张牌、3D 触摸、安全区、模拟软键盘、六张贡牌和聊天，另扩展猜拳的小屏测试。未以模拟结果替代 iPhone Safari 真机验收。
